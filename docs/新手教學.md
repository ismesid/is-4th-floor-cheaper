# 新手教學:GitHub + VS Code

給從沒用過 GitHub、VS Code 的組員。照順序做一次，大約 40 分鐘。卡住的話，把畫面截圖丟給 AI 或在群組問。

快捷鍵寫法:`Ctrl` 是 Windows,Mac 請換成 `Cmd`(⌘)。

---

## 0. 先搞懂四個名詞

| 名詞 | 是什麼 | 比喻 |
|---|---|---|
| **Git** | 記錄每個檔案每一次修改的工具，裝在自己電腦上 | 無限次的「復原」+ 版本紀錄 |
| **GitHub** | 放 Git 專案的網站，大家從這裡同步 | 雲端硬碟，但會記錄誰改了什麼 |
| **VS Code** | 寫程式、改文件的編輯器，內建 Git 按鈕 | Word,但給程式用 |
| **repo** | 一個專案資料夾(含所有版本紀錄) | 我們的專題資料夾 |

幾個常用動作:

| 動作 | 意思 |
|---|---|
| **Clone** | 第一次把 GitHub 上的專案下載到自己電腦 |
| **Pull** | 把別人上傳的新修改抓下來 |
| **Commit** | 在自己電腦存一個版本(要寫一句說明) |
| **Push** | 把自己的 commit 上傳到 GitHub |
| **Branch(分支)** | 開一條自己的支線來改，不影響主線 `main` |
| **Pull Request(PR)** | 請組員檢查你的分支，同意後再合併回 `main` |

## 1. 註冊 GitHub 並加入專案

1. 到 https://github.com 按 **Sign up** 註冊。**帳號名稱就是你在小組裡的代號**,repo 是公開的，所以不要用真名。
2. 把帳號名稱告訴 repo 管理者，他會邀請你成為協作者(collaborator)。
3. 到註冊的信箱收邀請信，按 **Accept invitation**。沒接受的話，你可以看檔案，但不能上傳。
4. **保護你的 email**:到 GitHub 右上角頭像 → **Settings** → **Emails**,勾選 **Keep my email addresses private**。下面會出現一個 `數字+帳號@users.noreply.github.com` 的地址，複製起來，第 4 步會用到。

## 2. 安裝軟體

### Windows

1. **Git**:到 https://git-scm.com/download/win 下載，一路按 Next,全部用預設值。
2. **VS Code**:到 https://code.visualstudio.com 下載 Windows 版安裝。安裝時建議勾選:
   - 「將 "以 Code 開啟" 動作加入 Windows 檔案總管的檔案/目錄操作功能表」
   - 「加入 PATH」
3. **Python**:到 https://www.python.org/downloads/ 下載 3.12 或 3.13。
   - ⚠️ 安裝第一個畫面，**一定要勾選最下面的「Add python.exe to PATH」**,再按 Install Now。

### Mac

1. **Git**:打開「終端機」(Launchpad 搜尋 Terminal),輸入 `git --version` 按 Enter。如果跳出要安裝「命令列開發者工具」,按 **安裝**。已經顯示版本號就代表裝好了。
2. **VS Code**:到 https://code.visualstudio.com 下載 Mac 版，解壓縮後把 **Visual Studio Code** 拖到「應用程式」資料夾。
3. **Python**:到 https://www.python.org/downloads/ 下載 3.12 或 3.13 的 macOS 安裝檔，一路按繼續。

### 確認安裝成功

打開 VS Code,按 `` Ctrl + ` ``(鍵盤左上角 Esc 下面那個鍵)開啟終端機，輸入以下指令，每行都應該顯示版本號:

```
git --version
python --version
```

Mac 如果 `python` 找不到，改用 `python3`(之後所有指令的 `python` 都改成 `python3`)。

## 4. 設定 Git 的名字和 email(只做一次)

在 VS Code 終端機輸入(換成你自己的):

```
git config --global user.name "你的GitHub帳號"
git config --global user.email "數字+帳號@users.noreply.github.com"
```

email 用第 1 步複製的 noreply 地址。**不要用自己的信箱**,repo 是公開的，每個 commit 都會顯示 email。

---

## 5. 把專案下載到電腦(Clone)

1. 打開 VS Code,按 `Ctrl + Shift + P`,輸入 `Git: Clone` 按 Enter。
2. 選 **Clone from GitHub**。第一次會跳出瀏覽器要你登入 GitHub,按 **Authorize** 允許。
3. 在清單中選我們的 repo(或貼上 repo 網址)。
4. 選一個資料夾存放(例如「文件」),不要放在雲端硬碟同步資料夾裡(OneDrive、iCloud、Google Drive),會互相干擾。
5. 下載完右下角問「要開啟複製的存放庫嗎?」,按 **開啟**。
6. 如果問「是否信任此資料夾的作者」,按 **是，我信任作者**。

## 6. 第一次設定 Python 環境

在 VS Code 終端機(確認目前位置是專案資料夾)依序輸入:

**Windows**
```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

**Mac**
```
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

- 成功的話，終端機每行開頭會出現 `(.venv)`。
- 之後每次開新終端機，VS Code 通常會自動啟用；沒有的話再輸入第二行。
- 按 `Ctrl + Shift + P` → `Python: Select Interpreter` → 選有 `.venv` 的那一個。
- Windows 如果出現「因為這個系統上已停用指令碼執行」,先輸入 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`,按 Y,再重試。

## 8. 每天的工作流程

### 情況 A:改計畫、程式、分析結果(要走 Pull Request)

**① 開工：切到 main 並同步**
- 看左下角狀態列，如果不是 `main`,點它 → 選 `main`。
- 到原始檔控制頁(`Ctrl + Shift + G`),按上方的 **同步變更**(或 `⋯` → **提取(Pull)**)。

**② 開一條分支**
- 點左下角的分支名稱 → **建立新的分支** → 輸入名稱，例如 `in02-code`。
- 命名規則:`計畫編號小寫-做什麼`,例如 `pre01-plan-v2`、`ex01-fix-cv`。

**③ 修改檔案，或請 AI 幫忙**
- 記得先讓 AI 讀 `AGENTS.md`(見最後一節)。

**④ Commit(在自己電腦存一個版本)**
- 原始檔控制頁會列出改過的檔案。點檔案可以看改了哪裡(紅色刪除、綠色新增)。
- 確認沒問題，在檔案上按 **+**(暫存),或按「變更」旁邊的 **+** 全部暫存。
- 上方輸入框寫說明，例如 `IN02:加入交互作用圖`,按 **✓ 認可(Commit)**。

**⑤ Push(上傳)**
- 第一次上傳這條分支，按 **發佈分支(Publish Branch)**。之後按 **同步變更**。

**⑥ 開 Pull Request**
- 到 GitHub 的 repo 網頁，上方會出現黃色提示 **Compare & pull request**,點它。
- 標題寫 `[IN02] 雙因子 ANOVA 程式`,內文寫改了什麼、對應哪份計畫。
- 右邊 **Reviewers** 選一位組員。按 **Create pull request**。
- 在群組通知那位組員。

**⑦ 審核與合併**
- 審核的人：到 PR 頁面 → **Files changed** 看修改 → 右上 **Review changes** → 選 **Approve** → 送出。
- 有人 Approve 後，開 PR 的人按 **Merge pull request** → **Confirm merge** → **Delete branch**。

**⑧ 回到 main**
- VS Code 左下角切回 `main`,按 **同步變更**,抓下剛合併的內容。

### 情況 B:改報告的 md、docs、錯字(可以直接推到 main)

1. 確認左下角是 `main`,先 **同步變更**。
2. 修改 → 暫存 → 寫說明 → Commit → **同步變更**。

### 每天都要記得

- **開工前先同步，收工前一定要上傳。** 改了沒上傳，組員就看不到。
- 一次 commit 只做一件事，說明寫清楚。

## 9. 協作規則

| 規則 | 原因 |
|---|---|
| 計畫、程式、分析結果一定走 Pull Request | 有人檢查，主線不會被改壞 |
| 已鎖定的計畫檔不能改 | 避免看到結果後修改規格 |
| 每份計畫的結果只由負責人執行和上傳 | 避免兩人產生不同版本 |
| Word、PowerPoint 改之前先在群組說 | 這類檔案無法合併，同時改會有一人的修改不見 |
| 不上傳 `data/`、密碼 | 資料太大；密碼會公開 |
| 不用真名，用 GitHub 帳號 | repo 是公開的 |
| 絕對不要 force push | 會把別人的修改蓋掉 |

完整規則在 [AGENTS.md](../AGENTS.md)。

## 10. 出問題怎麼辦

| 狀況 | 怎麼處理 |
|---|---|
| **Push 失敗，說遠端有新的修改** | 先按 **同步變更**(會先 Pull 再 Push)。 |
| **出現衝突(Merge Conflict)** | VS Code 會標出衝突的檔案。打開後會看到兩個版本，上面有按鈕 **接受目前的變更 / 接受傳入的變更 / 接受兩者**。不確定的話，不要亂按，截圖問 AI 或在群組問。 |
| **改壞了檔案，還沒 commit** | 原始檔控制頁，在檔案上按 **↶ 捨棄變更**,會回到上次 commit 的樣子。 |
| **已經 commit 但想取消** | 不要用 force push。再做一個新的 commit 把它改回來，或問 AI「怎麼用 git revert 取消某個 commit」。 |
| **不小心上傳了不該上傳的檔案(資料、密碼)** | 馬上在群組說。密碼要立刻去改掉。 |
| **找不到 `python` 指令** | Windows:重裝 Python,記得勾 Add to PATH。Mac:改用 `python3`。 |
| **左下角看不到分支名稱** | 代表 VS Code 開的不是專案資料夾。`檔案` → `開啟資料夾`,選 clone 下來的那個資料夾。 |

## 11. 怎麼和 AI 合作

我們的規則寫在 [AGENTS.md](../AGENTS.md),**一定要讓你的 AI 先讀**。

| 你用的 AI | 怎麼讓它知道規則 |
|---|---|
| Claude Code | 自動讀 `CLAUDE.md`,不用額外做事 |
| GitHub Copilot(VS Code) | 自動讀 `.github/copilot-instructions.md` |
| Codex、Cursor | 自動讀 `AGENTS.md` |
| Gemini CLI | 自動讀 `GEMINI.md` |
| ChatGPT、Gemini 網頁版 | 每次開新對話，上傳 `AGENTS.md` 和要做的計畫檔，貼上下面的開場白 |

**開場白(網頁版 AI 用，其他 AI 也可以用來確認它有讀到)**

```
請先完整閱讀 AGENTS.md,這是我們小組專題的規則，整段對話都要遵守。
我的 GitHub 帳號是 ______。我今天要做的是 ______(例如:IN02 的程式)。
開始前，請先告訴我這件事需要哪份計畫、那份計畫目前是否已鎖定。
```

**提醒**
- AI 說「計畫還沒鎖定，不能寫程式」時，不要叫它跳過。這是我們故意設的規則。
- 計畫的**獨立審查**要用全新的對話(或另一個 AI),不要用寫計畫的那段對話。審查指示在 `plan/_templates/審查指示.md`。
- AI 寫的程式和文件，commit 前自己看過一遍。
