## 0. 要討論的問題

把 12 季臺北市、新北市的實價登錄原始資料，整理成所有分析共用的一份乾淨資料：哪些交易要留、哪些要排除、每個變數怎麼定義。

## 1. 目的與研究問題

- 產出一份所有 inclass_analysis、extra_analysis 共用的分析資料檔，讓大家用同一個樣本。
- 把小組討論過的疑慮變成明確的變數：頂樓、相對位置、2 樓、建物型態、有無電梯。
- 交給 PRE02 做樣本切分。

## 2. 事前已知資訊揭露

- 全專案共通的已知資訊見 `plan/README.md`(11/18 預試結果)。
- 撰寫本計畫時(2026-11-20)看過以下**筆數**,沒有計算任何價格相關的統計量:
  - 交易日期在 112/10–115/09、排除明顯特殊交易後約 118,302 筆，其中「預售屋」備註 10,881 筆。
  - 有無電梯完全由建物型態決定：公寓 = 無電梯；華廈、住宅大樓 = 有電梯(各有 2–4 筆例外)。
  - 3/4/5 樓各格筆數：無電梯 5 層公寓約 3,200–4,200 筆；無電梯 4 層公寓約 3,500–3,700 筆；有電梯、總樓層 ≥ 7 約 6,900–7,100 筆。
  - 門牌是完整地址，沒有遮蔽；去掉樓層後約 84,000 個不同門牌。
  - 交易標的含車位的約 51%,其中約 24% 的車位總價為 0(車位價格併入總價)。

## 3. 資料

- **來源**:`data/raw/<季別>/a_lvr_land_a.csv`(臺北市)、`f_lvr_land_a.csv`(新北市),季別 112S4–115S3。讀檔 `pd.read_csv(path, skiprows=[1])`。
- **樣本單位**:一筆買賣交易(一個「編號」)。
- **合併與去重**:依季別由舊到新合併，同一「編號」只保留第一次出現的那筆。

**納入規則**(全部成立才保留，依序套用並記錄每步筆數)

| 步驟 | 規則 | 程式條件 |
|---|---|---|
| I1 | 交易標的包含房屋 | `交易標的` 以 `房地` 開頭 |
| I2 | 住宅類建物 | `建物型態` 以 `公寓`、`華廈`、`住宅大樓` 開頭 |
| I3 | 主要用途為住家 | `主要用途 == "住家用"` |
| I4 | 交易日期在研究期間 | `交易年月日` 介於 1121001 與 1150930(含) |
| I5 | 只買一層樓 | `移轉層次` 完全符合 regex `^([一二三四五六七八九十]+層)(，(陽台\|陽臺\|平台\|騎樓\|電梯樓梯間\|見其他登記事項))*$` |
| I6 | 只有一個建物 | `交易筆棟數` 中「建物」後的數字為 1 |
| I7 | 樓層資訊可解析 | 移轉樓層、總樓層數都能轉成整數，且 1 ≤ 樓層 ≤ 總樓層 |

**排除規則**

| 步驟 | 規則 | 理由 |
|---|---|---|
| X1 | `備註` 含以下任一字串:`親友`、`特殊關係`、`債`、`急買急賣`、`瑕疵`、`凶宅`、`政府機關`、`租約`、`毛胚` | 價格不反映一般市場行情 |
| X2 | `備註` 含 `預售屋` | 預售屋交屋後登記，成交價是簽約時的預售價格，和成屋不同(IN04 做敏感度分析) |
| X3 | 交易標的含車位，且 `車位總價元 == 0` | 車位價格併入總價，無法算出房屋本身的單價(IN04 做敏感度分析) |
| X4 | 屋齡缺漏或屋齡 < 0 | 無法控制屋齡 |
| X5 | 房屋坪數 < 5 或 > 200 | 不是一般住宅單位 |
| X6 | 單價的 log 值在全樣本 [Q1 − 3·IQR, Q3 + 3·IQR] 以外 | 極端值，多半是登錄錯誤或未標註的特殊交易 |

- X6 的四分位數用 X1–X5 之後的**全樣本**計算，不分樓層，所以不會因為看樓層差異而改變排除結果。
- 「增建」(陽台外推、頂樓加蓋等)**不排除**,改成一個變數控制(見第 4 節)。

**缺漏值**:除了上述規則，分析用到的變數若有缺漏，只在該分析中排除，並報告筆數。不做補值。

**預期記錄的數字**:每個步驟後的筆數，分臺北市、新北市。

## 4. 變數定義

| 變數 | 定義 | 來源欄位 | 型態 | 轉換 |
|---|---|---|---|---|
| `price_ping` | 房屋每坪單價(萬元/坪)=(總價元 − 車位總價元)/ 10⁴ ÷ 房屋坪數 | 總價元、車位總價元 | 連續 | 分析用 `log_price = ln(price_ping)` |
| `area_ping` | 房屋坪數 =(建物移轉總面積 − 車位移轉總面積)÷ 3.30579 | 建物移轉總面積平方公尺、車位移轉總面積平方公尺 | 連續 | 分析用 ln |
| `floor` | 移轉樓層 | 移轉層次(中文數字轉整數) | 整數 | |
| `total_floors` | 總樓層數 | 總樓層數 | 整數 | |
| `f4` | 是否 4 樓 | floor == 4 | 二元 | |
| `f1`、`f2` | 是否 1 樓、2 樓 | floor | 二元 | |
| `top` | 是否頂樓 | floor == total_floors | 二元 | |
| `relpos` | 相對位置 | floor ÷ total_floors | 連續(0–1] | |
| `relpos_grp` | 相對位置分組 | relpos ≤ 1/3 為低;≤ 2/3 為中；其餘為高 | 類別 | |
| `elevator` | 有無電梯 | `電梯` 欄;缺漏時公寓 = 0、華廈/住宅大樓 = 1 | 二元 | |
| `btype` | 建物型態 | 公寓 / 華廈 / 住宅大樓 | 類別 | |
| `bgroup` | 建物分組 | W4:公寓且總樓層 4;W5:公寓且總樓層 5;E7:有電梯且總樓層 ≥ 7;其他 | 類別 | IN02、IN04 使用 |
| `age` | 屋齡(年) | (交易日 − 建築完成日)÷ 365.25,民國日期轉西元 | 連續 | 迴歸用 age、age² |
| `rooms` | 房數 | 建物現況格局-房 | 整數 | |
| `has_mgmt` | 有管理組織 | 有無管理組織 == 有 | 二元 | |
| `has_ext` | 有增建 | 備註含 `增建` 或 `外推` 或 `加蓋` | 二元 | |
| `has_park` | 有車位 | 交易標的含 `車位` | 二元 | |
| `city` | 縣市 | 檔名 a / f | 類別 | |
| `district` | 行政區 | 縣市 + 鄉鎮市區 | 類別 | |
| `quarter` | 交易季別 | 交易年月日 → 例如 113Q1 | 類別 | |
| `building_id` | 建物識別碼 | 門牌去掉第一個「X樓」及其後文字，全形數字轉半形 | 類別 | 叢集標準誤、樣本切分使用 |

## 5. 推測與預期

本計畫不檢定推測，只負責產出資料。

## 6. 分析方法

不做統計檢定。只做:
- 篩選流程表(每步筆數)。
- 各變數的缺漏率、範圍檢查(例如屋齡 0–80 年、坪數 5–200)。
- 樓層 × 建物分組的筆數表(不含價格)。

## 9. 鎖定項目與可調整項目

- **鎖定**:研究期間、納入規則 I1–I7、排除規則 X1–X6、變數定義。
- **可調整**:程式寫法、輸出格式。若發現 regex 漏抓某種合理格式(例如「四層，露台」),屬於偏離，要寫入偏離紀錄。

## 10. 風險與備案

| 風險 | 處理 |
|---|---|
| 有些大樓不標 4 樓(例如改叫 3A、5 樓直接跳號) | 資料只有登記樓層，無法辨識。列為研究限制 |
| 同一門牌號碼的大社區有多個門牌，`building_id` 會把同一社區拆成多棟 | 叢集標準誤可能略為低估。列為限制 |
| 屋齡計算遇到建築完成年月只有年月(無日) | 日設為 1 日 |
| X3 排除後樣本減少約 12% | IN04 敏感度分析加回這些交易 |
