**主要分析樣本**:通過 I1–I7,且 `x1`–`x6` 全部為 False 的列，旗標 `main = True`。

**x6 的界線怎麼算**:
1. 先找出「通過 I1–I7 且 `x1`–`x5` 全部為 False」的列(主要分析樣本的候選列)。
2. 在這些列中，**依縣市分別**計算 `log_price` 的 Q1、Q3(`numpy.percentile`,預設 linear 內插)和 IQR,得到臺北市、新北市各自的上下界。
3. 這兩組界線固定後，套用到所有能算出 `log_price` 的列(包括 `x1`–`x5` 為 True 的列)，算出 `x6`。`log_price` 無法計算的列,`x6 = False`。
4. 界線不分樓層，所以排除結果不會因為樓層差異而改變。四個界線值寫進 `變數檢查.md`。

**`clean.csv` 收錄的範圍**:所有通過 I1–I7 的列，包含 `x1`–`x6` 為 True 的列。每列都有 `x1`–`x6` 六個旗標和 `main` 旗標。下游計畫用旗標組合精確定義自己的樣本，例如 IN04 加回預售屋 = `main | (x2 & ~x1 & ~x3 & ~x5 & ~x6)` 再依下面的屋齡規則處理。

**預售屋列的屋齡**:預售屋列(`x2`)大多數在交易時還沒建好，屋齡 < 0,會同時觸發 `x4`。PRE01 另外定義 `age0 = max(age, 0)` 和 `age_neg = (age < 0)`,供 IN04 加回預售屋時使用。是否使用由 IN04 規定，PRE01 只負責產生變數。

**缺漏值**:除上述規則外，分析用到的變數若有缺漏，只在該分析中排除，並報告筆數。不做補值。另提供 `cov_complete` 旗標(定義見第 4 節),讓下游計畫可以讓多個模型使用同一個樣本。

**預期記錄的數字**:去重後筆數、I1–I7 每一步後的筆數、`x1`–`x6` 各自為 True 的筆數、`main` 的筆數，以上都分臺北市、新北市列出。另列 x6 排除的筆數依縣市 × 樓層(1、2、3、4、5、6 以上)分列(只有筆數)。

## 4. 變數定義

**中文數字轉整數**:`移轉層次` 的樓層段去掉「層」,`總樓層數` 去掉「層」後，用以下規則轉換：一到九對應 1–9;「十」= 10;「十X」= 10 + X;「X十」= 10·X;「X十Y」= 10·X + Y。不符合這個格式(例如含其他字元)視為無法解析，由 I7 排除。

**民國日期轉西元**:`交易年月日`、`建築完成年月` 以字串讀入，去掉前後空白後依長度解析:

| 格式 | 解析 |
|---|---|
| 7 位數 `YYYMMDD`,日為 01–31 | 西元年 = YYY + 1911,依月、日組成日期 |
| 7 位數，日為 `00` | 日設為 1 |
| 5 位數 `YYYMM` | 日設為 1 |
| 其他(空白、3 位數、`---`、無效日期) | 缺漏 |

| 變數 | 定義 | 來源欄位 | 型態 | 轉換 |
|---|---|---|---|---|
| `price_ping` | 房屋每坪單價(萬元/坪)=(總價元 − 車位總價元)/ 10⁴ ÷ `area_ping`。車位總價元缺漏時視為 0 | 總價元、車位總價元 | 連續 | 分析用 `log_price = ln(price_ping)`;`price_ping` ≤ 0 或無法計算時為缺漏 |

**`elevator` 的說明**:`電梯` 欄沒有缺漏，而且幾乎完全由建物型態決定(公寓全部為「無」,華廈、住宅大樓只有極少數為「無」)。因此 `elevator` 和 `btype == 公寓` 幾乎等價，**下游模型不可同時放 `elevator` 和 `C(btype)`**,否則會幾乎完全共線(要由 IN03 修正)。少數例外照 `電梯` 欄原值，不另外修改，筆數寫進 `變數檢查.md`。另列為限制:`電梯` 欄可能是依建物型態填寫，不一定反映實際有無電梯(例如後來加裝電梯的公寓)。

**`building_id` 演算法**(PRE02 對預試資料也用同一個函數):
1. 取 `土地位置建物門牌`,全形數字 `０–９` 轉成半形，刪除所有半形與全形空白。
2. 若含 `、` 或 `，` 或 `,`,只取第一個分隔符號之前的部分(多門牌取第一個)。
3. 用 regex `^(.*?號)` 取到第一個「號」為止(含)，得到門牌主體。這一步會把「X號之3」併到「X號」,同一棟的不同分號視為同一棟。
4. 若找不到「號」:用 regex 刪掉第一個 `(地下)?[0-9一二三四五六七八九十]+[樓層]` 及其後所有文字，剩下的作為門牌主體；記錄這種列的筆數。
5. `building_id = city + "|" + 門牌主體`。

範例(門牌為虛構，只示範格式):

| 原始門牌 | building_id |
|---|---|
| `臺北市大安區甲乙路二段１００號五樓之３` | `A|臺北市大安區甲乙路二段100號` |
| `新北市板橋區丙丁路一段１０號之２三樓` | `F|新北市板橋區丙丁路一段10號` |
| `臺北市中山區戊己街５號四樓、５號四樓之１` | `A|臺北市中山區戊己街5號` |
| `臺北市文山區庚辛路３號` | `A|臺北市文山區庚辛路3號` |
| `新北市中和區壬癸路１２號　　` | `F|新北市中和區壬癸路12號` |

程式要附上這 5 個範例的單元測試(`assert`)。

## 5. 推測與預期

## 6. 分析方法

不做統計檢定。只做:
- 篩選流程表(每步筆數，分縣市)。
- 各變數的缺漏率、範圍檢查。超出常理範圍(例如屋齡 > 80 年)**只報告筆數，不另外排除**(坪數已由 `x5` 處理)。
- 樓層 × 建物分組的筆數表(不含價格)。
- `elevator` 與 `btype` 的交叉筆數表。

## 9. 鎖定項目與可調整項目

- **鎖定**:研究期間、去重規則、納入規則 I1–I7(含 I5 白名單)、排除規則 `x1`–`x6`(含 x1 關鍵字清單、x6 界線算法)、所有變數定義、`building_id` 演算法。
- **可調整**:程式寫法、輸出格式以外的呈現方式。
- 白名單、關鍵字清單以外的情況一律依「規則封閉」處理(I5 白名單外排除；x1 清單外保留)，不在執行後補規則。執行時若發現規則無法執行(例如欄位名稱改變),屬於偏離，要寫新版本。

## 10. 風險與限制

| 風險 | 處理 |
|---|---|
| 有些大樓不標 4 樓(例如改叫 3A、5 樓直接跳號) | 資料只有登記樓層，無法辨識。列為研究限制。不標 4 樓的做法可能較常見於新大樓，而預售屋已排除，樣本中很新的物件偏少，兩者可能互相影響 |
| 同一社區有多個門牌,`building_id` 會把同一社區拆成多棟 | 叢集標準誤可能略為低估。列為限制 |
| `電梯` 欄可能依建物型態填寫 | 見第 4 節，列為限制 |
| 115S3 的交易可能有部分在 115S4 才登記 | 最後一季的筆數可能偏少。不太會造成樓層之間的偏誤，列為限制；下游以 `quarter` 控制時段 |
| `建物移轉總面積` 含公設，公設比在公寓和大樓差很多 | 主要分析照原定義；提供 `main_area_ping` 供敏感度分析 |
| x3 排除後樣本減少 | IN04 敏感度分析用 `price_ping_total` 加回 |
