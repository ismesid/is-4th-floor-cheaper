## 0. 要討論的問題

小組討論時有兩種想法同時存在:
- 想「先看各樓層平均房價，再決定怎麼分組」「都做做看，哪邊有明確結果再報告」。
- 擔心「變因太多反而不好分析」。

前者如果直接做，就是看完結果再挑分析，會讓顯著的結果不可信。本計畫要讓小組**可以自由探索，又不破壞主要結論的可信度**。

## 1. 目的與研究問題

訂出所有分析共用的規則:
1. 資料切成「探索樣本」和「確認樣本」。
2. 哪些是主要假設、哪些是次要分析、哪些是探索。
3. 顯著水準、多重比較、「沒有差異」怎麼判定、報告原則。
4. 各計畫鎖定和確認樣本開始分析的先後順序。

## 3. 資料：樣本切分

- **單位**:以 PRE01 的 `building_id` 切分，同一棟的所有交易一定在同一邊。
- **建物清單**:`data/processed/clean.csv` 所有列(通過 PRE01 I1–I7,**包含 `x1`–`x6` 為 True 的列**)的 `building_id`。

**探索樣本** = 以下兩類建物的所有交易:
1. **預試建物**:讀取 `data/raw/115S2/a_lvr_land_a.csv` 的**全部列**(不套用 PRE01 的任何篩選)，用 PRE01 的同一個 `building_id` 函數(`city = "A"`)算出建物集合 P。`building_id` 落在 P 的建物全部列為探索。
2. **隨機建物**:不在 P 的建物，用以下與清單順序無關的穩定指派:

```python
h = int(hashlib.sha256(f"20261120|{building_id}".encode("utf-8")).hexdigest()[:8], 16) / 16**8
explore = h < 0.10
```

**確認樣本** = 其餘所有建物。

- 這個指派只依賴 `building_id` 字串本身，不依賴清單排序或抽樣順序，所以不同人重跑結果一定相同。
- **PRE01 改版的處理**:切分完成後，若 PRE01 出現新版本，已經出現在 `split.csv` 的 `building_id` **維持原本的指派**;新出現的 `building_id` 依上面同一規則指派。不可整批重新切分。
- `split.csv` 的 SHA-256 寫進 `切分筆數.md`,作為沒有重抽的證據。
- **預試檔案版本**:`data/raw/` 是 11/20 下載的，預試是 11/18。無法確認兩者是不是同一個檔案版本。若內政部在兩日之間更新過 115S2 的檔案，新版通常只會增加或更正交易，P 會涵蓋預試看過的建物；但如果有交易在新版中被刪除，那些建物可能留在確認樣本。這個風險列為限制。
- **推論的母體**:確認樣本是「沒有在 115S2 臺北市出現過交易的建物」中的約 90%,不是全部資料的隨機子集，臺北市的比例偏低。報告時列為限制，並在 `切分筆數.md` 列出兩邊各縣市 × 建物分組的筆數，讓讀者判斷代表性。

## 6. 分析方法：用途分配與先後順序

| 樣本 | 可以做什麼 |
|---|---|
| 探索樣本 | 任意看圖、試分組、試模型、測試程式(EX03)。從這裡得到的想法要寫成新計畫(「探索衍生計畫」,見第 7 節) |
| 確認樣本 | 只能執行已鎖定計畫寫好的分析 |

**先後順序**(必須遵守):
1. **確認樣本開跑的條件**:IN01–IN04、EX01、EX02 **全部鎖定**之前，任何人都不得在確認樣本上執行涉及價格的程式。只有負責人可以執行(依 `AGENTS.md`)。
2. 確認樣本**第一次產生價格相關結果之後**才鎖定的計畫(包括探索衍生計畫)，一律標為「事後探索」,不做確認性結論。
3. 任何計畫若在鎖定前看過探索樣本的結果，必須在該計畫第 2 節揭露看過哪些探索結果。

**防止誤用確認樣本**:切分程式輸出 `data/processed/explore.csv` 和 `data/processed/confirm.csv` 兩個檔案。探索用的程式只讀 `explore.csv`,並在程式開頭 `assert (df["split"] == "explore").all()`。確認樣本的分析一律透過 `code/common/load.py` 的共用讀檔函數讀取，這個函數會把使用的樣本與筆數自動寫進出處標註。

## 7. 決策規則(全專案共用)

**分析層級**

| 層級 | 內容 | 多重比較 |
|---|---|---|
| 主要假設 | H-P1:IN02 的 E7 組「4 樓凹陷」對比;H-P2:IN03 完整模型的 4 樓係數 | 這兩個檢定為一族(m = 2),Holm 校正 |
| 次要分析 | 各計畫列出的其他檢定 | 每份計畫在其第 7 節**列出各族包含哪些檢定，並寫出 m 的數字**;沒有列明的，該計畫所有次要檢定合為一族 |
| 探索衍生計畫 | 從探索樣本得到想法、寫成新計畫，**在確認樣本第一次產生結果之前鎖定**,再到確認樣本檢定 | 每份探索衍生計畫自成一族，Holm 校正。報告時標明「探索衍生」 |
| 事後探索 | 看過確認樣本結果後才想到的分析 | 不做確認性結論，報告時明確標示 |

**顯著與信賴區間**
- α = 0.05,雙尾。
- 「**顯著**」一律指該檢定所屬族的 **Holm 調整後 p 值 < 0.05**。
- 報告時另附未校正的 95% 信賴區間，只做呈現，不用來判定顯著。
- 以價格為被解釋變數的檢定與模型一律用 `log_price`。係數換算成百分比：(e^β − 1) × 100%。EX01 的估價誤差指標(例如 MAPE)在原始價格尺度計算，k-means 等不以價格為被解釋變數的分析不受此限。
- **標準誤**:迴歸類分析一律用以 `building_id` 為叢集的穩健標準誤:statsmodels `fit(cov_type="cluster", cov_kwds={"groups": building_id 的整數代碼})`,其他參數用預設值(含小樣本修正，p 值與信賴區間用常態分配)。只有一筆交易的建物照常保留，自成一個叢集。

**「4 樓效果」的判讀(TOST 與分類)**

- SESOI 為 ±2%,換成 log 尺度的界線:L = ln(0.98) ≈ −0.0202,U = ln(1.02) ≈ 0.0198。所有比較在 log 尺度進行，報告時再換算成 %。
- **等價檢定(TOST)**:兩個單尾檢定 H0:β ≤ L、H0:β ≥ U,各用 α = 0.05(常態分配、叢集穩健標準誤)。TOST p 值 = 兩個單尾 p 值的較大者。**TOST p 值也在所屬族內做 Holm 校正**(主要假設：對 H-P1、H-P2 的兩個 TOST p 值做 m = 2 的 Holm)。報告時附 90% 信賴區間。
- **分類**:依下表**由上往下**判斷，符合第一個條件就停止。每個檢定都會得到唯一的分類:

| 順序 | 條件 | 分類 |
|---|---|---|
| ① | Holm 調整後 TOST p < 0.05 | 沒有實務上有意義的 4 樓效果(效果在 ±2% 內) |
| ② | Holm 調整後 p < 0.05,且 β̂ ≤ L | 顯著折價，點估計達實務門檻 |
| ③ | Holm 調整後 p < 0.05,且 β̂ ≥ U | 顯著溢價，點估計達實務門檻 |
| ④ | Holm 調整後 p < 0.05,且 L < β̂ < U | 統計上顯著，但點估計小於實務門檻 |
| ⑤ | 其他 | 無法確定 |

- ② 只表示點估計超過門檻，不代表「確定超過 2%」。報告時要同時寫出 95% 信賴區間的上界是否 < L。
- **SESOI 的理由**:±2% 是小組事前判斷的「買方會在意的最小價差」。以每坪 60 萬元、30 坪的物件計算，2% 約 36 萬元，和一般成交時的議價幅度相比只是一小部分；小於這個幅度的差異，就算存在，對買賣決策的影響也很小。這是判斷，不是從資料推得的值。
- **敏感度呈現**:主要假設另外列出 SESOI 為 ±1%、±3% 時的分類，只做呈現，**結論一律以 ±2% 為準**。
- **主要假設結論不一致時**:H-P1 和 H-P2 的分類都要完整報告，不挑其中一個當作「最終結論」。兩者的解讀方式依 IN03 第 7 節事先寫好的對照表。

**報告原則**
- 所有已鎖定計畫中的分析，不論顯著與否都要報告。不可以只報告顯著的結果。
- 隨機種子一律用 20261120。

## 10. 風險與限制

| 風險 | 處理 |

| 同一社區多個門牌被拆成不同 `building_id`,可能同時出現在兩邊 | PRE01 v2 已把「X號之Y」併到「X號」,減少一部分；其餘列為限制，影響應該不大 |
