## 二、建議修改(不阻擋)

| 編號 | 位置(章節) | 建議 |
|---|---|---|
| S1 | §8 輸出格式 | **排版錯誤**:`lineterminator="\n"` 在檔案中變成了「引號內一個真正的換行字元」(第 159–160 行)。在原始文字中仍可讀成換行，但 GitHub 顯示時，行內程式碼中的換行會被轉成空白，畫面上會顯示成 `lineterminator=" "`。組員在 PR 上審核、日後照鎖定文字寫程式時，可能讀成「用空白當換行」。這是 v2 審查 S1 要寫死的重點，建議鎖定前改回字面的 `lineterminator="\n"`(反斜線 + n)。屬於排版修正、不改規格，是否需要再送審由小組決定，但要在修改回應中註明。 |
| S2 | §3、§8 | 沒有規定切分程式**怎麼讀** `clean.csv`。若用 pandas 預設型別推斷，像 `建築完成年月` 這類以 0 開頭的民國日期字串(例如 `0850101`)會被轉成整數、去掉開頭的 0,寫進 `explore.csv`、`confirm.csv` 後和 `clean.csv` 不一致；含缺漏的整數欄也會變成浮點數。建議寫死:「`clean.csv` 以 `dtype=str`、`keep_default_na=False` 讀入，只新增 `split`、`split_reason` 兩欄，其他欄位原樣輸出」,`code/common/load.py` 讀 `explore.csv`、`confirm.csv` 時再依 PRE01 的方式轉型。這樣 `explore.csv` + `confirm.csv` 的內容和 `clean.csv` 逐欄相同，也可以加一個 assert 核對。 |
| S3 | §6 先後順序第 1 點的例外 | 例外的理由寫「這些輸出只有界線值和筆數，不含任何樓層之間的價格比較」,但 PRE01 v2 會輸出「x6 排除筆數依縣市 × 樓層分列」。x6 是價格極端值，各樓層被排除的比例本身就帶有一點「哪個樓層較常出現極端低價或高價」的資訊，而且是用**含確認樣本的全部資料**算的。PRE01、PRE02 會在 IN01–IN04、EX01、EX02 鎖定**之前**執行，下游計畫的撰寫者會先看到這張表。資訊量很小，不阻擋，但建議:(a) 把理由改成「不含樓層之間的平均價格比較；x6 依樓層的筆數僅含極端值的筆數」較精確；(b) 規定 PRE01、PRE02 執行後，把這些輸出列入 `plan/README.md` 的「全專案已知資訊揭露」,下游計畫第 2 節須揭露是否看過(把第 3 點「看過探索樣本結果要揭露」擴大到 PRE01、PRE02 的輸出)。 |
| S4 | §6 先後順序第 2 點(偏離版本) | 偏離規則寫了「結論以開跑前鎖定的版本為準」和「偏離後結果照常報告並標明」,但當原版本**無法執行**時，偏離後結果是否仍算確認性結論沒有寫清楚，例如:H-P1 若因欄位問題要改寫，偏離後的 D_E7 是否仍和 H-P2 一起做 m = 2 的 Holm、是否仍套用 5 類分類表、可不可以寫成「支持/不支持忌諱說」?另外「技術原因」由誰認定也沒寫。建議擇一寫死，例如:「偏離後結果仍放在原本的族與 m 中計算並套用分類表，但結論句一律加註『偏離後結果』;偏離版本只能修改造成無法執行的部分，模型式、樣本定義、變數不得因其他理由改變;是否屬技術原因由負責人以外的一位組員在偏離版本的 PR 中確認」。 |
| S5 | §7 標準誤、TOST | 標準誤規則只寫「迴歸類分析」用叢集穩健標準誤，TOST 寫明用「叢集穩健標準誤」。但下游有非迴歸的方法:IN01 v1 用 Welch t 檢定比較 4 樓 vs 其他樓層，這也是一個「4 樓對比」,依 §7 字面要做 TOST、且要用叢集標準誤，和 IN01 的 Welch 做法衝突;IN02 也同時有古典 ANOVA 與穩健版。建議加一條通則:「凡是用來判定『顯著』或做 TOST 的估計值，一律用 OLS + `building_id` 叢集穩健標準誤估計(例如 t 檢定改成只有一個虛擬變數的迴歸);Welch t、古典 ANOVA F、Tukey 等課堂方法照常報告，但只做呈現」。或者明確允許某些方法例外，二擇一寫死。下游計畫鎖定前會寫明，因此不阻擋。 |
| S6 | §7 主要假設結論不一致、`plan/README.md` 連帶修改清單 | §7 寫「兩者的解讀方式依 IN03 第 7 節事先寫好的對照表」,但 IN03 v1 第 7 節只有一句「兩個都報告，並說明差異可能的原因」,沒有對照表。建議在 `plan/README.md` 的「連帶要改的下游計畫」加上:(a) IN03 第 7 節要補 H-P1 × H-P2 分類組合的對照表；(b) 各計畫第 7 節同時寫出雙尾 m 與 TOST m(目前清單只寫「各族的 m」);(c) IN02、IN04 的判讀改用 5 類分類表。確認樣本開跑條件已要求這些計畫全部鎖定，所以只要清單完整就不會漏。 |
| S7 | §3 PRE01 改版的處理 | 若 PRE01 改版改變了 `building_id` 函數，預試建物集合 P 要用舊函數還是新函數重算沒有寫。建議補一句:「新出現的交易判斷是否屬於預試建物時，P 用新版函數對 115S2 臺北市原始檔重算」(或用舊版，擇一)。發生機率很低，寫一句即可。 |
