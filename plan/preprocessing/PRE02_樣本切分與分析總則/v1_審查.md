## 一、必須修改(阻擋通過)

| 編號 | 位置(章節) | 問題 | 建議改法 |
|---|---|---|---|
| R1 | §3 樣本切分 | **隨機抽樣的演算法不唯一，無法保證「重跑結果完全相同」,也留下「重抽」的空間。**「用 `default_rng(20261120)` 隨機抽 20%」沒有規定:(a) 抽樣前 `building_id` 的排序方式(`unique()` 的出現順序會隨合併順序、去重規則改變);(b) 抽法是 `rng.choice(n, size=?, replace=False)`(固定數量，20% 如何取整?)還是 `rng.random(n) < 0.2`(每棟獨立，數量隨機);(c) 從哪一份資料取得 `building_id` 清單(PRE01 的 `clean.csv` 全部列、含 `excl_presale`/`excl_bundled_park` 旗標列?還是排除後的列?)。此外，若 PRE01 之後出現偏離版本(例如 regex 修正、`building_id` 定義修改),建物清單一變，同一個種子會產生完全不同的切分，等於變相重抽。 | 寫死完整演算法，例如:「`ids = sorted(clean.csv 所有列(含旗標列)的 building_id 唯一值，Python 字串排序)`;剔除預試建物後，`rng = np.random.default_rng(20261120)`;`u = rng.random(len(ids))`;`u < 0.20` 者為 explore」。更好的做法是改用**與清單無關的穩定指派**,例如 `int(sha256(f"20261120|{building_id}").hexdigest()[:8], 16) / 16**8 < 0.20`,這樣 PRE01 日後修改只會影響新增/消失的建物，不會整批重抽。並規定:PRE01 若在切分後出現新版本，已指派的 `building_id` 維持原指派，新出現的 `building_id` 依同一函數指派；在 `切分筆數.md` 記錄 `split.csv` 的 SHA-256,作為未重抽的證據。另外寫明 PRE02 必須在 PRE01 鎖定之後才能鎖定與執行。 |
| R2 | §3 探索樣本第 1 點 | **預試資料對應建物的規則無法直接寫成程式。**預試的「編號」有很多不會出現在 `clean.csv`(例如被 I1–I7、X1–X6 排除的列，或依 PRE01 去重規則保留在較早季別的同一編號)，計畫沒說這些編號的 `building_id` 要從哪裡算。若只用 `clean.csv` 對應，被清理掉的預試列所屬建物的其他交易會留在確認樣本，但預試其實看過那些建物的交易(預試的篩選條件和 PRE01 不同)。 | 改成:「讀取 `data/raw/115S2/a_lvr_land_a.csv` 全部列(不套用任何 PRE01 篩選),以 PRE01 的同一個函數從原始門牌算出 `building_id`;凡 `clean.csv` 中 `building_id` 落在此集合者，全部列為 explore」。並寫明 `building_id` 函數必須包含縣市(或行政區)前綴，避免臺北市與新北市同名門牌被誤歸為同一棟(請 PRE01 一併確認)。同時說明這份檔案是否就是預試當時使用的版本(預試在 11/18,`data/raw/` 下載於 11/20;若內政部在兩日之間更新過檔案，編號集合可能不同)。 |
| R3 | §3、§10、`plan/README.md` 待確認事項 2 | **實際探索比例與代表性和計畫所述不同，且 §10 的檢定力論證因此不成立。**審查者只計算筆數(未看價格)做了粗估:在 I1–I3 篩選後約 17.3 萬筆中，屬於「預試建物」的交易約 1.2 萬筆，全部在臺北市；其中臺北市**住宅大樓約 39%**、華廈約 17%、公寓約 9% 的交易會因預試規則進入探索樣本，再加上其餘 20% 隨機抽樣。也就是說:(a) 探索樣本不是 20%,而且偏向臺北市大樓;(b) 確認樣本中，臺北市有電梯大樓(E7 的主要來源之一)會少掉約一半，確認樣本不再是「全部資料的隨機 80%」;(c) §10「E7 組 3/4/5 樓仍各有約 5,000 筆」是用 80% 推算，沒有扣掉預試建物，且在叢集標準誤下有效樣本數遠低於筆數。小組在 README 確認「20%/80%」時，依據的是錯誤的資訊。 | 在 §3 明寫：探索樣本 = 預試建物 + 其餘 20%,預估整體比例與各縣市 × 建物型態的比例(可用筆數事先算出，不涉及價格)。在 §10 以扣除後的 E7 各樓層筆數與建物數(叢集數)重新說明檢定力；並事先寫一條「確認樣本推論的母體是『112S4–115S3 未在 115S2 臺北市有交易的建物 + 其餘 80%』,報告時列為限制」。若小組認為臺北市大樓流失太多，應在鎖定前決定是否把隨機比例調低(例如 10%),而不是在看到結果後才調整。 |
| R4 | §7 TOST 規則 | **TOST 判讀與 Holm 校正沒有接起來，判讀規則不唯一。**主要假設用 Holm(m=2)校正，但「有實務上有意義的 4 樓折價」用的是未校正的 95% CI;IN02 §7 則寫成「顯著(Holm 後)且點估計 < −2%」,兩份計畫用不同標準。Holm 下 p 值較小的那個檢定實際門檻是 0.025,對應 97.5% CI;用 95% CI 會和 Holm 結論矛盾(CI 不含 0 但 Holm 後不顯著)。等價判定(90% CI)是否也要做多重比較調整，同樣沒寫。 | 明定:(a)「顯著」一律指 **Holm 調整後 p < 0.05**(主要假設 m=2;次要分析依所屬族),報告時另附未校正的 95% CI 只做呈現；或者改用 Holm 對應的 CI 水準，但只能擇一並寫死。(b) 等價判定：寫明是否校正(例如「TOST 兩個單尾檢定各在 α=0.05,即 90% CI,不另做多重比較調整，理由是……」，或對 H-P1、H-P2 的 TOST p 值也做 Holm)。(c) 說明 CI 的計算方式：叢集穩健標準誤、用 t 或常態分配。 |
| R5 | §7 TOST 規則 | **判讀類別不完整，有一部分結果要看到後才決定怎麼說。**三分類沒有處理:(a) **顯著為正**(4 樓溢價),目前會被歸到「無法確定」,不合理;(b) 顯著為負但點估計介於 −2% 與 0 之間(統計顯著但未達實務門檻);(c) SESOI 是用百分比定義，但模型估的是 log 係數，換算後界線不對稱(ln 0.98 = −0.0202、ln 1.02 = +0.0198),沒寫要在哪個尺度比較。另外「點估計 < −2%」只是點估計超過門檻，並不是「確定超過 −2%」的檢定(minimum-effect test),標籤「有實務上有意義的折價」稍嫌強烈。 | 改成互斥且完整的分類表，例如:①90% CI 完全落在 (−2%, +2%) → 沒有實務上有意義的效果;② Holm 後顯著且點估計 ≤ −2% → 有意義的折價;③ Holm 後顯著且點估計 ≥ +2% → 有意義的溢價;④ Holm 後顯著但點估計在 (−2%, +2%) 且不符合① → 統計上顯著但幅度小;⑤其餘 → 無法確定。寫明比較在 log 尺度進行，界線為 [ln(0.98), ln(1.02)],報告時再換算成 %。若要更嚴格，可把②改成「95% CI 上界 < −2%」(真正的 minimum-effect test),但要事先擇一。 |
| R6 | §7 SESOI、§9 | **SESOI 寫著「待使用者確認」,但同時列為鎖定項目。**SESOI 直接決定主要結論的分類，必須在鎖定前定案，不能留到看結果後。另外，預試已看到「沒放交互作用約 −4.5%、放了接近 0」,±2% 正好落在兩者之間；目前的理由(「議價空間的一小部分」、每坪 60 萬算出 1.2 萬)沒有說明為什麼是 2% 而不是 1% 或 3%,也沒揭露「選擇時已知預試結果」。 | v2 刪除「待確認」,寫明最終值與不依賴預試結果的理由(例如引用實價登錄或文獻中議價率、估價誤差、或「買方願意為此改變決策的金額」),並在 §2 明確揭露:「訂 SESOI 時已知預試估計約 −4.5% 與接近 0」,說明這個值不是依預試結果挑的。也可以事先規定敏感度呈現(例如同時列出在 ±1%、±3% 下的分類，但結論以 ±2% 為準)，讓讀者自行判斷。 |
| R7 | §6 用途分配 | **沒有規定確認樣本開始分析和其他計畫鎖定的先後順序。**若 IN02、IN03 先鎖定並在確認樣本跑出結果，而 IN04、EX01、EX02 還在審查中，就可以依已看到的主要結果調整這些計畫(例如挑子樣本、改模型式)。同樣地，探索樣本的結果(EX03 試跑 IN02/IN03)若在 IN02/IN03 鎖定前就看到，主要假設的規格可以依探索結果調整，但計畫裡沒有要求揭露。 | 加一條:「所有使用確認樣本的計畫(IN01–IN04、EX01、EX02)全部鎖定之前，不得在確認樣本上執行任何涉及價格的程式」;若小組認為做不到，則規定「確認樣本上第一次產生結果之後才鎖定的計畫，一律標為事後探索」。另規定：任何計畫若在鎖定前看過探索樣本的結果，須在該計畫 §2 揭露看過哪些探索結果。 |
| R8 | §7 分析層級表 | **多重比較的「族」定義和其他計畫矛盾。**PRE02 規定次要分析「每份計畫內自成一族」,但 IN03 把 f2 檢定單獨一族、EX02 在同一計畫內分成兩族。依 PRE02 字面，IN03、EX02 的族定義是違規的，執行時會產生「到底用哪個 m」的選擇空間。 | 改成「每份計畫在 §7 明列各族包含哪些檢定(檢定數 m 要寫出數字);未列明者，該計畫所有次要檢定合為一族」。或者統一規定一計畫一族，並要求 IN03、EX02 修改。擇一寫死。 |

## 二、建議修改(不阻擋)

| 編號 | 位置(章節) | 建議 |
|---|---|---|
| S1 | §3 | 同一社區常有多個門牌(PRE01 §10 已提),會被拆成不同 `building_id`,同一社區可能同時出現在探索與確認樣本，兩邊不完全獨立。影響應該不大，但建議在本計畫限制中寫一句；若可行，可用「行政區 + 路段巷弄 + 號(去掉之X)」之類較粗的單位切分。 |
| S2 | §6 | 確認樣本的保護目前只靠自律。`clean.csv` 會透過雲端分享給所有人，任何人都能直接打開看到確認樣本的價格。建議:由切分程式輸出 `explore.csv`、`confirm.csv` 兩個檔案，探索用程式只讀 `explore.csv` 並 assert;確認樣本的分析一律透過共用的讀檔函數，並在出處標註中自動記錄。 |
| S3 | §7 標準誤 | 寫明實作方式，例如 statsmodels `fit(cov_type="cluster", cov_kwds={"groups": building_id})`,是否使用小樣本修正、p 值與 CI 用 t 還是常態分配。叢集數很多時差異很小，但寫死可避免兩人跑出不同數字。也請說明單一交易建物(叢集大小 1)照常保留。 |
| S4 | §7「被解釋變數一律用 log_price」 | 有些分析的對象不是價格的平均差(例如 EX02 k-means 的特徵、EX01 以 exp 還原後算 MAPE)。建議改成「以價格為被解釋變數的檢定與模型一律用 `log_price`」,並註明 EX01 的誤差指標在原始尺度計算。 |
| S5 | §7 分析層級 | 從探索樣本得到想法、寫成新計畫、在確認樣本上檢定，在統計上其實是有效的事前檢定(資料獨立)。目前一律歸為「事後探索、不做確認性結論」偏保守，可以考慮另設一層「探索衍生的確認檢定」,自成一族並用 Holm,報告時標明來源。若維持現狀，也建議把這個取捨寫進理由。 |
| S6 | §10 | 建議事先做一個不需看確認樣本價格的精確度估算：用預試已知的殘差標準差(已在探索樣本中，屬已知資訊)與 E7 確認樣本的筆數、平均叢集大小，估計 D_E7 的 90% CI 半寬，確認 ±2% 的 TOST 有機會得出「沒有有意義效果」。若半寬接近或超過 2%,應在鎖定前就知道，而不是看到「無法確定」後才發現。 |
| S7 | §8 產出 | `切分筆數.md` 建議也列出:各縣市 × 建物分組 × 樓層(1–5 樓)在兩邊的筆數與建物數、預試建物筆數、`split.csv` 的 SHA-256。這些都是筆數，可以公開，也方便日後審查 R3。 |
| S8 | §7 | 主要假設 H-P1、H-P2 結論不一致時的處理目前寫在 IN03,建議在 PRE02 也寫一句全專案的原則(例如兩者都報告、不挑其一當「最終結論」),因為這是全專案的判讀規則。 |
